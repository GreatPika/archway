Archway 0.2.0 package guide
===========================
Archway checks prepared TypeScript and Dart projects against architecture.yaml.

Archway 0.2.0 is an unsigned preview. Check
https://github.com/GreatPika/archway/releases for available artifacts, SHA256SUMS
and registry installation instructions. Use these examples with matching verified
artifacts, and registry packages only when the release lists them as published.
To run from source, see:
https://github.com/GreatPika/archway#run-from-source

Native installers
-----------------
Choose the matching installer and verify its SHA-256 against SHA256SUMS, then
open it through the normal desktop installation flow:
- Ubuntu 24.04 Desktop x64: archway-0.2.0-linux-x64-unsigned.deb
- macOS 15 Apple Silicon: archway-0.2.0-macos-arm64-unsigned.pkg
- Windows x64: archway-0.2.0-windows-x64-unsigned.exe
Linux/macOS installation requires administrator approval. Windows installs for
your user under %LocalAppData%\Programs\Archway and registers its command in PATH.
These installers are unsigned; macOS is also unnotarized. The OS may warn or
block installation. Use its normal trust review; do not disable protections.
After installation, open a fresh terminal and run: archway --version
Install the newer installer to update. Remove with the Linux package manager,
Windows Installed Apps, or on macOS:
sudo /bin/sh /usr/local/lib/archway/uninstall.sh
Installation is outside projects; each project keeps its own policy and guide.
See source tool/installers/<platform>/README.md for ownership and recovery limits.

Portable bundles
----------------
Choose Linux x64, macOS arm64 (Apple Silicon), or Windows x64. Download its
bundle and SHA256SUMS. Compute the archive file's SHA-256 and compare it
with the same filename in SHA256SUMS before extracting:
Linux:   sha256sum archway-0.2.0-linux-x64.tar.gz
macOS:   shasum -a 256 archway-0.2.0-macos-arm64.tar.gz
Windows: Get-FileHash .\archway-0.2.0-windows-x64.zip -Algorithm SHA256
Checksums detect corruption; they are not a publisher signature.

Linux, from the download directory:
mkdir archway-0.2.0
tar -xzf archway-0.2.0-linux-x64.tar.gz -C archway-0.2.0
./archway-0.2.0/bin/linux-x64/archway --help

macOS, from the download directory:
mkdir archway-0.2.0
tar -xzf archway-0.2.0-macos-arm64.tar.gz -C archway-0.2.0
./archway-0.2.0/bin/macos-arm64/archway --help

Windows PowerShell, from the download directory:
Expand-Archive .\archway-0.2.0-windows-x64.zip -DestinationPath .\archway-0.2.0
& .\archway-0.2.0\bin\windows-x64\archway.exe --help

Use a fresh destination. Keep the entire extracted directory together, including
bin/, native/, assets/, schemas/, manifest.json, README.txt and LICENSE.
These bundles are unsigned. Follow your operating system's normal security
review if it blocks launch; no security bypass is required by this guide.

Thin wrapper packages
---------------------
The thin npm/pub launchers fetch only the selected target's pinned native archive
on first invocation and reuse the verified cache offline. Installation has no
scripts. For a published package version, the pub route is:
dart pub global activate --no-executables archway VERSION
dart pub global run archway:archway <args>
Pub needs pinned Dart 3.13.3 for activation and invocation, without generated aliases
or setup/repair. Offline use needs its prepared snapshot under the same SDK and
verified native cache. After an SDK change, run
dart pub global run archway:archway --version
once before capturing JSON: SDK snapshot preparation can print dependency
progress on the first invocation. Replace VERSION with the published version
listed on the release page. See tool/npm/README.md for package requirements.

First use
---------
After installation, preview starter files in your project:

archway --root /path/to/project init --template mixed --dry-run

For a portable bundle, replace archway with its executable path. For a local
npm installation, use npm exec --offline -- archway. For pub, replace archway
with dart pub global run archway:archway. Use your actual project
path; without --root, Archway uses the current directory.

Choose a project without architecture.yaml or ARCHITECTURE.md. Remove
--dry-run to create both files, then edit architecture.yaml for your project
and use ARCHITECTURE.md when working on it. This is the 0.2.0 startup name. Existing files are never
overwritten or migrated. Init in 0.2.0 also refuses ASCII-case variants of both
startup names on every OS.

archway --root /path/to/project validate
archway --root /path/to/project owner src/example.ts
archway --root /path/to/project check
archway --root /path/to/project export --format mermaid

Use COMMAND --help for options.

Native policy/query/init/export commands need neither Node nor an external Dart
SDK. npm needs Node to launch. TypeScript checks require external Node 24.21.0;
Dart checks require external Dart 3.13.3 (see project docs for prepared Flutter).
The compiler assets are included; the Node and Dart runtimes are not bundled.
Checks read already-prepared projects and never install dependencies or run
project builds, scripts or plugins. Operational results are JSON. Check exits
0 when analysis completes without violations, 1 when it completes with violations,
and 2 when the policy is invalid or analysis is incomplete. Export emits Mermaid with separate JSON diagnostics.

Supported targets and notices
-----------------------------
Payloads target Linux x64, macOS arm64 and Windows x64. Linux ARM, Intel macOS
and Windows ARM payloads are not included. Installation routes were tested in CI
on Ubuntu 24.04 x64, macOS 15 arm64 and Windows Server 2025 x64. CI tests do not
establish public download or registry availability; consult the release notes
for public-download verification and published packages. Windows 11 and
downloaded-file GUI installation have not been verified. Installers are unsigned,
and the macOS installer is not notarized.

Archway is MIT licensed; see LICENSE. Third-party notices are included under
assets/. JSON result schemas are under schemas/. manifest.json records versions,
source identity and file hashes.

For platform requirements and installation limitations, see:
https://github.com/GreatPika/archway/blob/main/docs/implementation/installation-layout.md

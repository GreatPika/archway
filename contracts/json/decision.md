# Archway v1 public machine contract

Normative with public-result.schema.json, export-diagnostics.schema.json, policy.schema.json and the semantic requirements below. Policy version and schema_version are 1. Nodes without the required public field are not accepted.

## Transport and versioning

validate, owner, node, allows, check and init emit exactly one complete UTF-8 JSON object followed by LF on stdout, including invocation and operational failures. No BOM, streaming records, logging or truncation. stderr may carry human operational logs; consumers use stdout and actual process exit code. No timestamps or durations enter machine data. All object keys are fixed for schema_version 1; consumers dispatch on the integer version before strict validation. A future incompatible shape increments schema_version; policy version and private helper protocol version are independent. Diagnostic codes have an open uppercase vocabulary, whereas existing codes retain their meaning. Unknown version is never silently coerced.

The envelope is command, schema_version, tool_versions, resolved_root, policy_path, policy_hash, status, exit_code, diagnostics, payload. Nullable fields are present as null; optional node policy contracts normalize to []; public is required and never defaults from omission. Arrays are never omitted. tool_versions always identifies Archway; fields for unneeded/unavailable adapters/runtime are null. resolved_root is an absolute native canonical root or null if not resolved. policy_path is normalized root-relative or null before selection and for init. policy_hash is sha256: plus 64 lowercase hexadecimal digits, over the exact raw policy bytes read; null only if not read, including init. A malformed/unreadable policy does not obtain an invented hash. Loaded malformed bytes do retain their real hash.

command is the recognized command even when its arguments are invalid; null only for missing/unrecognized command. Explicit --help and --version are text-only informational modes, exit 0, outside JSON command results; neither loads a policy or starts an adapter. No undocumented JSON flag is required. v1 supports only the specified JSON default and Mermaid transport for operational results.

## Exact status/exit mapping

- ok / 0: successful query, allowed decision, complete clean check, created init or prepared dry-run.
- negative / 1: owner unmatched; node --path unmatched; allows denied or undetermined; complete check with violations.
- incomplete / 2: check has valid policy but incomplete evidence, including unavailable runtime, partial helper failure or changed input. Every known violation remains in violations.
- invalid_policy / 2: reading succeeded but policy parsing, format version, structural validation or policy semantics failed. check has policy_valid false and analysis_complete false; other query payloads are null.
- error / 2: I/O, unknown node ID, init conflict/write failure, or unrecoverable command failure. check carries the available report; init carries its outcome after template/root selection; failures before init can prepare an outcome have null payload (specified below). No reliable facts are discarded by mapping a recoverable analysis failure to error.
- usage_error / 64: wrong arguments, unknown command, invalid --root/--policy syntax, negative/noninteger pagination, incompatible flags, unsupported command option. payload is null and no writes occur. init --policy is always this case.

Precedence: invocation failure precedes reading/writing; invalid policy prevents adapters; check incomplete dominates violations; a complete check with violations takes precedence over clean success; warnings never change the exit code. Failure to read a syntactically valid policy path is error, not invalid_policy. Missing/non-directory --root is usage_error; permission/I/O while accessing an existing root is error. A check-wide I/O fault can have policy_valid false when validation never completed. A per-project tool error is incomplete, retains other projects, and is not a reason to abandon them. check status error is reserved for a global failure preventing normal orchestration.

Successful policy commands require root, policy path and policy hash. Errors require at least one diagnostic. check violations/unknowns/warnings/tool_errors carry distinct diagnostic arrays; envelope diagnostics contains invocation/policy/orchestration diagnostics only, not duplicates of those arrays. init and query diagnostics are in the envelope. Warnings found while loading a valid plan belong in envelope diagnostics for queries, and payload.warnings for check. EMPTY_PLAN appears in validate and check exactly when projects and nodes are both empty. It does not determine the corpus: check always enumerates C from scope minus exclude, even with no projects or nodes. Project and node counts are then zero; observed.files is the actual known |C|. Only the bootstrap scope: [] guarantees a zero-file corpus independently of repository contents.

## Typed command payloads

- validate: policy_valid true; projects and nodes counts.
- owner: normalized path, ownership owned/excluded/outside_scope/unowned, owner_id only for owned. Exclusion takes priority.
- node catalogue: mode catalogue; sorted nodes with id/responsibility/owns_count; total, omitted, offset, limit. offset defaults 0; limit defaults null (all). Explicit limit is an integer >= 1; offset is an integer >= 0. omitted = total minus returned length, counting entries before offset and after the returned window. Offset beyond total yields an empty list, not an error. Pagination flags on detail node are usage errors.
- node ID: mode id and full node; unknown ID is error/2, null payload, UNKNOWN_NODE_ID. node --path: mode path, full ownership result and node, with node null for unmatched. Detailed node contains id, responsibility, normalized owns, sorted unique public exact-file paths, contract references, allows and allowed_dependents neighbor arrays. No source contents, recursive traversal or hidden truncation.
- allows IDs: mode ids, policy_only true, decision_scope module, from_id/to_id, policy_decision allowed or denied, and reason. Both IDs must exist. Same ID is always allowed (reason same_owner); a direct allows edge gives allowed/declared_allow; otherwise denied/not_allowed. This is module graph permission only and says nothing about any target file. Paths mode has decision_scope file, replaces IDs with from/to ownership results, and evaluates exact normalized file paths. Directory-prefix, root and syntactically directory operands (final . or ..) are usage_error/64. If either path is not owned, decision is undetermined with reason ownership_unknown. Same owner is allowed/same_owner without public membership. Different owners require a direct allows edge first (otherwise denied/not_allowed), then exact target membership in the target owner public list (otherwise denied/target_not_public); success is allowed/declared_allow. policy_only remains true: no stat, existence, compiler, symbol or runtime claim is made. Denied and undetermined both exit 1 and remain distinguishable.
- check: policy_valid, analysis_complete, violations, unknowns, warnings, tool_errors; observed files/analyzed_files/edges; coverage projects/files; facts.edges; input_identity; scope/exclude; projects/nodes. Includes recognized unsupported selected code as file coverage unsupported/not_attempted rather than hiding it. Every corpus file appears exactly once. analyzed_files counts complete or partial file analyses. edges counts the full facts.edges list (including external/builtin/unresolved evidence), not only violations. Projects are all declared projects, including zero-file projects. Complete implies all files assigned and complete, all project coverage complete, no unknowns/tool_errors, all identity rechecks finished and no observed changes. policy_valid is independent of analysis_complete; malformed policy has empty corpus/facts, zero counts and no adapter launch. An empty bootstrap with scope: [] can be complete with EMPTY_PLAN after all required identity checks. An empty project/node plan with existing scoped code is incomplete: retain each corpus file, SOURCE_UNOWNED and the relevant missing-context or unsupported-source diagnostic. Enumeration gaps make analysis incomplete even when zero files are known.

Coverage assignment is separate from analysis. candidates are explicit project_id/context_id pairs. assigned means exactly one supported known candidate with discovery certain; selected project_id/context_id must equal it. missing means no known candidate, ambiguous means multiple, unsupported or failed records configuration/discovery trouble. Uncertain discovery may retain known candidates without claiming assigned; each file also exposes discovery_complete and sorted unresolved_project_ids, so failed discovery is machine-readable; diagnostic project_id identifies each failed project. A context-discovery failure cannot be hidden because another candidate was found.

Facts retain project_id and context_id and use source and source_range, kind import/export/import_type/require/dynamic_import/part/part_of, nullable specifier, type_only, and resolution. Local resolution has canonical_file_uri, nullable repository-relative path, and nullable via_path URI recording the original resolution alias. Outside-root local has path null and remains a known local outside_scope violation, never external. external/builtin use identity; unresolved uses its kind and a corresponding unknown. Ranges are 1-based UTF-16 line/column, end-exclusive, with ordered endpoints and a path equal to the source when attached to an edge. Diagnostic spans may be zero-width; edge spans must be nonempty. The complete fact list retains reliable edges even if the containing file has partial coverage.

## Input identity and determinism

Identity covers actual read inputs: policy, source, config/extends, manifests/lockfiles/package_config, resolution metadata, SDK files and directory inventories. location is either repository + normalized path or external + absolute canonical_file_uri. This distinction is evidence, not permission to own an external path. The external filesystem-root URI file:/// represents a present inventory input only; file inputs, absent probes, edge targets and file aliases cannot use it. changed_inputs may retain this exact root location when a matching present inventory baseline is recorded. Never invent a repository-relative path for an external directory. A present input has SHA256 of its exact bytes; inventory hashes canonical UTF-8 JSON of the sorted immediate entry tuples [name,kind] (kind file/directory/symlink/other), so additions/deletions are observable. An absent resolution probe is presence absent with hash null and is rechecked for continued absence. Entries are unique by kind+location, ordered lexicographically by kind then canonical location. SDK/Node/adapter versions also remain visible in tool_versions. No secrets or file contents appear in identity.

The identity aliases array records each followed mapping as observed_file_uri/canonical_file_uri, ordered by observed URI. Recheck each observed alias for retargeting as well as target bytes; changed_inputs identifies the observed alias location. Private analyzer metadata may include richer per-fact provenance; it is not silently substituted for missing input evidence.

Recheck every recorded input and every traversed corpus inventory before returning. Changed/appeared/disappeared entries are changed_inputs, and INPUT_CHANGED makes analysis incomplete. If rechecking cannot finish, rechecked false plus a tool error makes incomplete. This is observed consistency, never an atomic snapshot; atomic_snapshot is always false. Tracking only positive reads is insufficient because newly created missing targets and corpus files change the outcome. Hashing uses exact bytes and filesystem names, not reserialized YAML or edited policy normalization.

Normalized output paths use /, no empty/. /.. segments, with ./ as the sole root-prefix exception, in accordance with the path matrix. File source/input positions cannot use a directory prefix. Canonical URI encoding and case/Unicode rules follow the matrix. Node catalogues/neighbors and projects sort by ID, path sets by normalized path, candidate pairs by project then context, facts by source then range then kind/specifier/target, diagnostics by path/range/code/rule_pointer/project/message (null before strings). Ties deduplicate exactly identical values, not distinct edges. Init paths keep fixed architecture.yaml then ARCHITECTURE.md order. Sets in the plan normalize duplicate entries; deterministic ordering does not authorize truncation.

## Safe init, including partial outcomes

--template dart|typescript|mixed is required; --dry-run is a boolean, --policy is forbidden. Other writes/overwrite options are unsupported. planned_paths always lists exactly architecture.yaml then ARCHITECTURE.md. dry-run includes both complete planned_files contents in that order; normal invocation uses an empty planned_files array. The template changes comments, not semantic policy fields.

The 0.2.0 preview amends the schema_version 1 init filename enum from
ARCHITECTURE_AGENT.md to ARCHITECTURE.md. The envelope fields and shape remain
unchanged; this is an observable contract change, not backward compatibility
with the 0.1.0 filename enum. Published 0.1.0 artifacts remain unchanged.

Before writing, list the selected root without following child links and check
both fixed output names using ASCII-case-insensitive comparison on every OS.
Any matching entry (file, directory or link, including a dangling link) is a
conflict. This conservative init-only rule also refuses architecture.md on Linux;
it does not change case-sensitive policy paths or corpus identity. Return the
canonical planned target in conflicting_paths and diagnostic path; identify the
actual existing entry spelling in the diagnostic message. Dry-run performs these
checks without loading the native bridge. Existing ARCHITECTURE_AGENT.md is not
an output alias: leave it untouched, without migration, deletion or merging.

outcome planned: dry-run true, no created/residual/conflicting paths. outcome created: dry-run false, created_paths contains both files, residual_paths empty. created_paths means files whose exclusive creation succeeded during this invocation, even if they were subsequently removed. residual_paths means only this invocation's files remaining after a failed rollback; successful output files are not "residual".

outcome conflict: an existing target was found before writing; created/residual empty, conflicting_paths names existing targets. A race causing exclusive-create conflict after an earlier successful creation instead triggers rollback and outcome rolled_back or partial, with conflicting_paths allowed to identify the raced target. outcome rolled_back: ordinary failure with all created files removed (created_paths may be empty if first write failed). outcome partial: rollback left at least one created target, residual is a subset of created. Never remove someone else's file; identity changes during rollback become residual+diagnostic. Dry-run still checks target conflicts and reports conflict/2, with planned contents for inspection. Crash atomicity is not promised and no JSON output is promised after forced termination or broken stdout.

If the root cannot be accessed before a plan can be prepared, init error/2 has null payload and diagnostic, policy_path/hash null. Otherwise all operational init failures return the outcome payload. This explicitly separates pre-operation errors from attempted writes.

## Export has a separate transport

export --format mermaid [--out PATH] [--overwrite] never writes JSON to stdout. --overwrite without --out is usage_error/64. --format is required; only mermaid is supported. Successful stdout export: complete Mermaid text plus LF, exit 0. Successful file export: stdout empty, file contains that same text. No analysis runtime/adapters are needed; npm/pub launch prerequisites remain as specified in compatibility/delivery.md. Existing output is rejected without explicit overwrite; failure is error/2. Policy failure is invalid_policy/2; argument failure is usage_error/64.

stderr is empty when export has no diagnostics. Otherwise it contains exactly one export-diagnostics schema JSON object plus LF, with no interleaved human logs. This applies to success warnings and errors. On any reported error stdout is empty; render and validate in memory before writing stdout. File-write failures do not claim that an old output is preserved unless the safe-write implementation verifies it. payload has format mermaid (null if format not recognized) and out normalized root-relative (null for stdout or unavailable parsing). command is export, warnings status ok/0. Consumers must not expect an ordinary public-result on this channel. These guarantees cannot prevent partial bytes if the OS terminates the process or the output stream itself fails mid-write.

## Policy shape and parser rules

policy.schema.json validates parsed YAML, not the YAML text grammar. Required root keys: version, projects, scope, exclude, nodes; unknown keys fail. version is integer 1. A TypeScript project is exactly id/adapter/tsconfig (adapter value typescript); a Dart project exactly id/adapter/package_roots (adapter dart), with nonempty package_roots. Nodes require id/responsibility/owns/allows/public; contracts may be omitted and defaults to []. All projects/nodes/scope/exclude arrays may be empty; an individual module may own no paths. Responsibility is a nonempty string. IDs are ASCII [A-Za-z][A-Za-z0-9_.-]*, case-sensitive; project IDs and node IDs are unique within separate namespaces. Unknown allows IDs, overlap between different owners and roots escaping the repository fail semantic validation. Self allows is redundant and normalizes away because intra-module access is always allowed; duplicate allows/contracts/owns/public normalize without double count. public: [] explicitly closes the module to incoming cross-owner file dependencies; it does not restrict same-owner edges.

Read one UTF-8 YAML 1.2 document only. Reject duplicate mapping keys at every level, non-string keys, custom tags, aliases/anchors/merge keys, extra documents and non-finite numeric scalars before JSON-shape validation; never coerce a scalar type. Comments are allowed. Arrays remain arrays. Reject absolute policy paths, control characters and reserved glob metacharacters * ? [ ] { }; raw relative . and .. are normalized according to the matrix, rejecting only escape above root. tsconfig is a file path; package_roots directory paths normalize with trailing /. scope/exclude/owns preserve exact-file vs trailing-slash-directory meaning. public accepts only exact files and follows the normalized path semantics below. Contracts are nonempty local relative paths or absolute http/https URLs; local references stay under root and missing local references warn, never cause network access. All format/schema failures get POLICY_SCHEMA_INVALID, malformed YAML POLICY_PARSE_ERROR, unsupported version POLICY_VERSION_UNSUPPORTED; semantic policy errors retain precise diagnostic codes and pointers.

## Diagnostic baseline and validation boundary

Diagnostics always carry code/severity/message/rule_pointer/source_range/project_id/path/recovery_hints; inapplicable contextual fields are null. rule_pointer is RFC6901 over the parsed policy. recovery_hints are literal display strings, never executable instructions. Typical stable codes: USAGE_ERROR, UNKNOWN_NODE_ID, POLICY_READ_FAILED, POLICY_PARSE_ERROR, POLICY_SCHEMA_INVALID, POLICY_VERSION_UNSUPPORTED, EMPTY_PLAN, CONTRACT_NOT_FOUND, POLICY_CYCLE, DEPENDENCY_NOT_ALLOWED, TARGET_NOT_PUBLIC, PUBLIC_PATH_NOT_FILE, PUBLIC_PATH_EXCLUDED, PUBLIC_PATH_OUTSIDE_SCOPE, PUBLIC_PATH_NOT_OWNED, POLICY_PATH_INVALID, LOCAL_TARGET_EXCLUDED, LOCAL_TARGET_OUTSIDE_SCOPE, LOCAL_TARGET_UNOWNED, SOURCE_UNOWNED, UNRESOLVED_IMPORT, UNSUPPORTED_SOURCE_KIND, ANALYSIS_CONTEXT_MISSING, ANALYSIS_CONTEXT_AMBIGUOUS, UNSUPPORTED_ANALYSIS_CONFIGURATION, ANALYSIS_CONTEXT_DISCOVERY_FAILED, SOURCE_SYMLINK, INPUT_CHANGED, NODE_UNAVAILABLE, DART_SDK_UNAVAILABLE, INIT_TARGET_EXISTS, INIT_WRITE_FAILED, INIT_ROLLBACK_FAILED, EXPORT_TARGET_EXISTS, EXPORT_WRITE_FAILED. Later specific codes can be added without deleting these meanings.

JSON Schema validates shape, enums and expressible implications. Cross-field arithmetic, sortedness, uniqueness by key, range ordering, candidate identity, residual subsets and direct policy predicates additionally require semantic conformance checks; the schema alone cannot certify them. `test/contracts/public_contract_test.dart` exercises `validate_contract.dart` with illustrative semantic checks and adversarial fixtures, not a complete validator for Archway implementations. The actual implementation acceptance suite must enforce every normative requirement here, the assignment/path matrix and private protocol. Passing these contract fixtures closes a design-consistency gate only; it is not evidence that Dart, TypeScript, paths or process handling work on real platforms.

## CLI grammar

archway [--root ROOT] COMMAND [OPTIONS] [OPERANDS]

validate [--policy PATH]
owner [--policy PATH] PATH
node [--policy PATH] [--limit N] [--offset N]
node [--policy PATH] ID
node [--policy PATH] --path PATH
allows [--policy PATH] FROM_ID TO_ID
allows [--policy PATH] --paths FROM TO
check [--policy PATH]
init --template dart|typescript|mixed [--dry-run]
export [--policy PATH] --format mermaid [--out PATH [--overwrite]]

--root may appear before or after the command. All named options accept the separate value form shown; --name=value is also accepted for one-value options, but --paths requires two following operands. -- ends option parsing. No short option aliases in v1. Each option may appear at most once; unknown/repeated flags, extra/missing operands and incompatible modes return usage_error/64 before side effects. Global --help and --version return plain text and exit 0 only when used without an operational command; COMMAND --help returns that command's help without other operational options. --policy defaults architecture.yaml for read commands only. Arguments not defined here (including --json, --human, --force and export formats other than mermaid) are usage errors. There is no automatic parent-directory lookup. Explicit --limit and --offset are accepted only by node catalogue; details have neither pagination nor truncation.

## Stable context IDs

TypeScript context_id is typescript:<project_id>. Dart context_id is dart:<project_id>:<64 lowercase SHA256 hex of the canonical context descriptor>; the descriptor and UTF-8 canonical JSON serialization are fixed by the assignment contract (root/included_paths/excluded_paths/package_config_path/options_paths/sdk_version; keys sorted, no insignificant whitespace, arrays sorted unique). Context IDs describe configuration identity, not content freshness; input hashes detect content changes. No context ID depends on traversal order or object indices.


Each coverage.projects entry owns one contexts table: [{context_id,descriptor}], ordered by context_id. Project and adapter are inherited from the containing project row. TypeScript descriptor is exactly {tsconfig}; Dart descriptor is exactly {root,included_paths,excluded_paths,package_config_path,options_paths,sdk_version}, package_config_path nullable. Path identities in Dart descriptors are normalized repository-relative strings or absolute canonical file URIs when external; collections are sorted unique by Unicode code point. sdk_version is the exact selected SDK version. The Dart hash includes precisely this descriptor, not the surrounding project/adapter/context ID. Every reported candidate and edge context must reference a descriptor row; failed discovery may yield an empty contexts table and must not invent a descriptor. Content freshness is separate in input_identity. The table explains candidate origin without duplicating descriptors per edge.

Physical path identities in context descriptors do not encode policy-prefix predicates: they omit a trailing / except for the repository-root identity ./. The portable path matrix also rejects reserved glob characters in positional path arguments; an actually discovered unrepresentable source path produces incomplete with a diagnostic, never a false clean empty corpus.

Every valid-policy check must include the present policy input whose hash equals envelope.policy_hash. Every emitted fact's source must belong to corpus coverage and its project/context pair must be one of that source's explicit candidates, including partial/ambiguous analyses. Complete reports cannot contain unresolved facts. These are conformance invariants, not optional information-quality recommendations.

## Public file entry points

Each public entry is a nonempty repository-relative exact file path. Reject a trailing separator, root, or final raw . or .. segment with PUBLIC_PATH_NOT_FILE before normalization can erase its directory intent. Portable lexical failures not already rejected by schema are POLICY_PATH_INVALID. Normalize other paths with the existing separator/NFC/dot-segment rules, then deduplicate and sort. Reject excluded entries with PUBLIC_PATH_EXCLUDED, outside-scope entries with PUBLIC_PATH_OUTSIDE_SCOPE, and entries that are unowned or owned by another node with PUBLIC_PATH_NOT_OWNED, in that precedence order. All these entry errors point at /nodes/i/public/j in the original parsed policy. Missing public, nonarray/nonstring values and unknown node keys are POLICY_SCHEMA_INVALID. No automatic inference from index.ts, lib/*.dart, package exports, or language visibility exists.

Validation and policy-only queries allow planned nonexistent files and arbitrary file extensions. They perform no filesystem lookup to distinguish extensionless files from directories. This is declaration validity, not proof of supported analysis. Mixed Dart/TypeScript paths share the same language-independent list. `owner` and `node --path` retain ownership semantics and do not become public-access checks. Node detail includes public; catalogue remains id/responsibility/owns_count. Check retains its existing nodes integer count rather than adding a node table.

For check, use the final resolved local physical target under the existing alias/canonical identity contract. Classify excluded/outside_scope/unowned target first, retaining its independently known violation even when source ownership is absent. SOURCE_UNOWNED is a separate file-level diagnostic. Only an owned source and owned target can proceed to same-owner/direct-allows/public evaluation. Emit DEPENDENCY_NOT_ALLOWED at /nodes/sourceIndex/allows when the module edge is absent; only if it is present emit TARGET_NOT_PUBLIC at /nodes/targetIndex/public. Never emit both for the same edge. TARGET_NOT_PUBLIC carries the source fact span, source path and project_id. Complete checks with such violations are negative/1; incomplete evidence dominates as incomplete/2 and retains known violations.

The predicate applies uniformly to reliable import/export/import_type/require/dynamic_import/part/part_of facts. A public barrel may re-export same-owner private files; importers must reach the barrel itself. Public is not transitive, and symbol-level visibility, exported names, dataflow, callable APIs or runtime reachability are not verified. Final .d.ts targets from TypeScript resolution are checked as .d.ts files; never substitute a source file or original package spelling. Unresolved evidence remains unknown/incomplete, never TARGET_NOT_PUBLIC invented from text. External and builtin classifications are unchanged.

## Cross-project observation conflicts

Merge parent Plan/corpus observations first, then valid project evidence sorted by project_id; each project's observation order is stable. Retain one baseline per kind+location and one alias baseline per observed URI for output representation. Detect conflicts by underlying physical/observed location independently of semantic input role: a source/config/resolution/sdk role difference cannot hide incompatible observations of the same location. File/directory type changes also conflict. Presence, hash or canonical-mapping disagreement marks the location in changed_inputs and emits INPUT_CHANGED with incomplete/2, even if final revalidation matches one observation. Never silently overwrite. Baseline order selects a deterministic representation, not privileged truth. Revalidate all recorded observations and aliases independently; the merged baseline must not erase checks of conflicting evidence.

Invalidate facts from every project whose inherited input manifest depends on a conflicting key or mapping, including the baseline supplier. Facts inherit the entire project manifest, so this removes all facts of each affected project. Keep unaffected project facts and independently established violation diagnostics under the incomplete result and change diagnostics. Do not recompute a clean result from only surviving facts.

A conflicting inherited input also invalidates that project's discovery. Preserve historical candidates and descriptors, mark discovery_complete false and include the affected project in unresolved_project_ids for the relevant language. Uncertain uniqueness prevents assigned: use failed even with one unaffected positive candidate. Previously analyzed affected files become partial; other files use failed/not_attempted as applicable. Affected project coverage is partial, never complete. Retained unaffected facts stay context-marked; do not invent a selected ambiguous context.
